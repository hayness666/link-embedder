Privacy Policy

The bot processes message data to recognize links. It does not store message bodies, but keeps persistent IDs needed for author controls. This is not a claim that no data is processed or logged by infrastructure.

1. Current status and purpose

Link Embedder is maintained by hayness666 and is available in installed servers where channel permissions allow. While connected, it receives new Discord messages using Message Content intent and uses text, message IDs, server/channel IDs, and operational author/permission metadata to select supported links, ignore bots, and limit repeated replies. The hosted replacement mode handles eligible messages in accessible text channels and voice-channel text chats. It performs no historical backfill.

It does not use social-account cookies or bypass privacy, login, age, or anti-bot gates. URL shape does not prove public availability. Age-restricted Discord channels are not automatically excluded, and the bot cannot classify linked media.

2. Retention and logs

  • Application code does not write message bodies, usernames, URLs, or media to a database or local files, and does not intentionally log message content, URLs, raw API errors, or credentials.
  • Message-ID deduplication has a ten-minute expiry; channel cooldowns last three seconds; burst timestamps cover one minute. Idle server state expires after ten minutes. Cleanup occurs on qualifying incoming events, not a timer, so expired state can remain in memory until another qualifying event or shutdown.
  • Message caching is disabled. The Discord SDK still retains operational server, channel, user/member, and permission metadata in memory.
  • Fixed status/error and configuration-error messages can appear in runtime logs. The eventual host may retain logs and network/operational metadata. The runtime is hosted by Silly Development. Its operational data and log retention are controlled by that provider; no fixed retention period has been verified.
  • Bot responses remain in Discord until deleted under Discord’s policies. Removing the bot does not erase those messages. The hosted bot uses replacement-only mode. In permitted channels, eligible plain-text messages may be replaced with a webhook post showing the original sender’s display name and avatar. The bot confirms the replacement and rechecks the source before deleting the original. Discord marks reposts with its APP badge; original authors cannot edit them as native messages, but can delete newly tracked reposts through Apps → Manage Post. Older untracked posts need a moderator. Attachments and thread starters are left intact. Private, archived, locked, and announcement threads are excluded. Eligible same-channel and same-thread replies show an italic “Click to see message” link and a bold mention of the verified human author, when known. The reply context does not copy target message text. The link stops working if the target is deleted. Inaccessible or cross-channel references are left intact.

Repost ownership records

The host stores repost message IDs, original-author IDs, server IDs, channel IDs, webhook-parent channel IDs for threads, webhook IDs, referenced-message IDs for eligible replies, and a numeric component ID identifying preserved sender text in a private local file. No message bodies, media, or tokens are included. Records survive restarts and remain until managed deletion, rollback, or an operator-verified deletion request. The store is capped at 10,000 records; originals are preserved if a record cannot be saved. Old untracked posts cannot be claimed by matching a display name.

3. Optional preview services

Requests contain the public post identifier/URL, not surrounding message text or Discord user identity. Discord fetches allowed media URLs from providers and their CDNs. For Snapchat and approved Facebook video and Reel attachments, the bot downloads validated media into memory within a shared 8 MiB limit and sends it to Discord; it does not persist those media files. Bluesky main-video media may use pds-cache.fxbsky.app; only its validated public DID/CID route is accepted. Discord may also crawl original links. Replacement-only mode does not send separate companion replies. Metadata requests reject redirects except Amazon’s exact same-host /dp/ASIN to /clp/SAME_ASIN metadata recovery, with matching identity and unchanged bounds. The separate short-link resolver follows only bounded, allowlisted platform redirects. No cookies, account access, or access-gate bypass is used.

The supported-sites table lists each optional helper. Requests may also reach the source platform and its media CDN.

These helpers are optional and require operator approval before activation. Each helper link contains the relevant cleaned post URL, not surrounding message text or a Discord user identity. These are independent third parties; no contracted-processor relationship is asserted. Their policies and agreements must be evaluated before activation. A local approval setting is not itself user consent or proof of compliance.

Original platforms and helpers may record their requests. Functional share parameters may remain in URLs. Removing known trackers does not guarantee zero tracking. With operator approval, public Facebook photo, video, Reel, and post URLs are sent to Facebed without surrounding Discord text or credentials. Matching metadata can supply author names, captions, and public Facebook CDN media URLs. Optional bounded public Facebook author lookups may supply verified handles; blocked lookups are not bypassed. Handle results are cached only in memory for up to five minutes, with at most 128 entries. Unusable preview responses leave the original message untouched. MP4 data is fetched into memory with an 8 MiB shared attachment limit and sent to Discord; cookies and login access are not used. UpScrolled uses public post metadata. Amazon uses custom product cards. Threads uses approved fzthreads.com public post metadata and rejects private/spoiler-marked responses and profile-image placeholders. Video availability depends on the provider. Without helper approval, only limited public first-party metadata is used.

4. Controls and deletion requests

Wrap a link in angle brackets, spoiler markup, or code to suppress the bot’s preview. Administrators can limit channel access or remove the bot. Ask a server administrator to delete a bot response in Discord. Repost ownership IDs persist as described above; request operator-verified removal through the contact form. Transient rate-limit state clears on shutdown.

Use the contact form to request access, correction, or deletion of data held by the operator, or report a privacy concern. Include a reply address if you need follow-up. The operator may need enough non-sensitive context to locate a record and verify a request. The operator cannot erase independent Discord or provider records; contact those services separately. Do not include sensitive data in public reports.

5. This website

Outside the Google Forms embed on the contact page, this static site includes no analytics scripts, external fonts, or advertising. These static pages are hosted on GitHub Pages. The bot runtime is separate and runs on Silly Development for installed servers where channel permissions allow. GitHub states that it logs site visitors’ IP addresses for security purposes even when signed out. See GitHub Pages data collection and GitHub’s Privacy Statement.

6. Contact form data

The contact page embeds Google Forms. Loading it connects your browser to Google, which may process IP addresses, browser information, cookies, and other service data under Google’s Privacy Policy. Submitting sends your selected category, message, optional reply email, and submission time to Google Forms for the operator to review. No Google sign-in, file upload, or automatic verified-email collection is required by this form. Response summaries are not public.

Responses are retained in the operator’s Google Forms account until the operator deletes them; no automatic retention deadline is configured. Native new-response email notifications are enabled for the owner. Those alerts are separate from the response records; full-message forwarding is not promised. Support emails and follow-up records may also remain in the operator’s mailbox until deleted. This persistent support data is separate from the bot’s transient processing. Request deletion through the form, and provide a reply address if follow-up is needed. Never submit passwords, bot tokens, private URLs, medical information, or identity documents.
