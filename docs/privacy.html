Privacy Policy

The bot processes message data to recognize links. It does not maintain a persistent message database. This is not a claim that no data is processed or logged by infrastructure.

1. Current status and purpose

Link Embedder is maintained by hayness666 and is currently offline. No preview helpers are activated. When running, it receives new Discord messages using Message Content intent and uses text, message IDs, server/channel IDs and operational author/permission metadata to select supported links, ignore bots and limit repeated replies. It responds in accessible channels and active threads. It performs no historical backfill.

It does not use social-account cookies or bypass privacy, login, age or anti-bot gates. URL shape does not prove public availability. Age-restricted Discord channels are not automatically excluded, and the bot cannot classify linked media.

2. Retention and logs

  • Application code does not write message bodies, usernames, URLs or media to a database or local files, and does not intentionally log message content, URLs, raw API errors or credentials.
  • Message-ID deduplication has a ten-minute expiry; channel cooldowns last three seconds; burst timestamps cover one minute. Idle server state expires after ten minutes. Cleanup occurs on qualifying incoming events, not a timer, so expired state can remain in memory until another qualifying event or shutdown.
  • Message caching is disabled. The Discord SDK still retains operational server, channel, user/member and permission metadata in memory.
  • Fixed status/error and configuration-error messages can appear in runtime logs. The eventual host may retain logs and network/operational metadata. The pilot runtime is hosted by Silly Development. Its operational data and log retention are controlled by that provider; no fixed retention period has been verified.
  • Bot responses remain in Discord until deleted under Discord’s policies. Removing the bot does not erase those messages. By default, original messages are not modified or removed. In explicitly enabled repost channels, eligible plain-text messages may be replaced with a webhook post showing the original sender’s display name and avatar. The bot confirms the replacement and rechecks the source before deleting the original. Reposts are labeled as made by Link Embedder; original authors cannot edit or delete them as their own messages. Ask a server moderator for removal. Complex messages such as attachments and replies are left intact.

3. Optional preview services

The bot makes no direct metadata or media requests to helper services. If approved and enabled, it rewrites a supported URL to the helper domain and posts that link with a cleaned original fallback in the same channel. Discord’s preview crawler can request the helper URL; a person clicking the link may visit it too. Native previews involve Discord and the original platform.

4. Controls and deletion requests

Wrap a link in angle brackets, spoiler markup or code to suppress the bot’s preview. Administrators can limit channel access or remove the bot. Ask a server administrator to delete a bot response in Discord. There is no persistent bot message database to erase; transient state is cleared on shutdown and processed as described above.

Use the contact form to request access, correction or deletion of data held by the operator, or report a privacy concern. Include a reply address if you need follow-up. The operator may need enough non-sensitive context to locate a record and verify a request. The operator cannot erase independent Discord or provider records; contact those services separately. Do not include sensitive data in public reports.

5. This website

Outside the Google Forms embed on the contact page, this static site includes no analytics scripts, external fonts or advertising. These static pages are hosted on GitHub Pages. The bot runtime is separate and is being configured on Silly Development for a limited test channel. GitHub states that it logs site visitors’ IP addresses for security purposes even when signed out. See GitHub Pages data collection and GitHub’s Privacy Statement.

6. Contact form data

The contact page embeds Google Forms. Loading it connects your browser to Google, which may process IP addresses, browser information, cookies and other service data under Google’s Privacy Policy. Submitting sends your selected category, message, optional reply email and submission time to Google Forms for the operator to review. No Google sign-in, file upload or automatic verified-email collection is required by this form. Response summaries are not public.

Responses are retained in the operator’s Google Forms account until the operator deletes them; no automatic retention deadline is configured. Native new-response email notifications are enabled for the owner. Those alerts are separate from the response records; full-message forwarding is not promised. Support emails and follow-up records may also remain in the operator’s mailbox until deleted. This persistent support data is separate from the bot’s transient processing. Request deletion through the form, and provide a reply address if follow-up is needed. Never submit passwords, bot tokens, private URLs, medical information or identity documents.
